# Лабораторная работа № 5 — адаптивная вёрстка

Ветка: `lesson5`, основа — `lesson4`. Открыть корневой `index.html`
или `src/index.html`. Установка пакетов и сборка не нужны.

Макет: https://www.figma.com/design/ezb4wQpEdJ9IOGVrG30wSA/WEBиC-mobile--Copy-?node-id=0-1

Реализованы шапка, первые два экрана (главное предложение с формой заявки
и Full development cycle) и подвал по вариантам 1440, 768 и 425 px.
Остальные разделы сохраняют учебное содержимое предыдущих работ.

- От 1280 px: горизонтальная шапка, форма в строку, два столбца второго экрана.
- 768–1279 px: кнопка меню, форма слева от иллюстраций, два столбца услуг.
- До 768 px: иллюстрации между описанием и формой, услуги в один столбец,
  контакты подвала в два столбца. До 375 px дополнительно уменьшены отступы
  и заголовки, чтобы страница помещалась на узких телефонах.
- Модальное меню закрывается кнопкой, Escape, выбором ссылки и при переходе
  к десктопной ширине; поддерживает клавиатуру и возвращает фокус кнопке меню.
- Форма использует встроенную проверку браузера; данные не отправляются.
- Использованы локальные изображения Figma из предыдущей работы;
  стрелка услуг и иконка закрытия экспортированы из доступной копии.
- Исправлены относительные пути к Inter для просмотра без веб-сервера.
  Для SF Pro используется Arial, поскольку SF Pro отсутствует в проекте.

Проверено в Chrome на 320, 374, 425, 600, 768, 1024, 1279, 1280 и 1440 px:
нет горизонтальной прокрутки, изображения и шрифты загружаются;
проверены меню, переходы, Escape, смена размера и валидация формы.
Снимки на 425, 768 и 1440 px сверены с макетом.

# Лабораторная работа № 3 — семантическая структура

Ветка: lesson3. Основа — состояние lesson2.
Страница: src/index.html. Корневой index.html перенаправляет на неё.
Для просмотра достаточно открыть index.html в браузере; сборка и установка пакетов не нужны.

## Что выполнено

Разметка следует цветным блокам на приложенной схеме. Точное оформление макета
не воспроизводится: цель работы — HTML-структура. Стили прошлой работы сохранены.
Figma не предоставила подключению доступ к файлу, поэтому использована схема.
Тексты адаптированы на русский; показатели компании — учебные примеры.
Новые SVG — условные иллюстрации, а не изображения, экспортированные из Figma.

| Блок на схеме | Класс | Элемент и вложенные блоки |
| --- | --- | --- |
| Шапка | site-header | header, логотип, nav.main-navigation, телефон и ссылка |
| Первый экран | hero | section, общий hero-content с hero-description и hero-request, изображение отдельно |
| Полный цикл | development-cycle | section, cycle-description и services-list |
| Отрасли | industries | section, список industries-list из 15 пунктов |
| Проекты | projects | section, nav.projects-navigation, article.project-card |
| Описание проекта | project-description | div, заголовок, абзац, список функций и dl с характеристиками |
| Обсуждение | project-discussion | section, discussion-description и form.discussion-form |
| Этапы | development-stages | section, ol.stages-list с шестью li.stage |
| Команда | team | section, team-description со статистикой и ролями, изображение |
| Книга | contact-book | section, form.book-form, скачивание памятки, обложка |
| Вопросы | faq | section, div.faq-list, четыре details.faq-item |
| Подвал | site-footer | footer, общий footer-content с address.footer-contacts и nav.footer-navigation |

Между шапкой, девятью основными секциями и подвалом стоят 10 элементов hr.

## Почему выбраны эти теги

- header — вводная часть страницы, footer — завершающая.
- main — единственное основное содержимое страницы.
- section — тематический раздел со своим заголовком.
- article — самостоятельная карточка проекта, которую можно вынести отдельно.
- nav — группа навигационных ссылок. aria-label различает назначения трёх nav.
- div — группировка вложенного содержимого без дополнительного семантического смысла.
- ul — перечень без значимого порядка; ol — этапы, порядок которых важен.
- dl, dt и dd — характеристики проекта: название характеристики и её значение.
- address — контактная информация организации.
- details и summary — вопросы, раскрываемые браузером без JavaScript.
- hr — тематическая граница, а не нарисованная средствами CSS линия.

aside не добавлен искусственно: на схеме нет самостоятельного побочного содержимого.
Не обязательно использовать все возможные семантические теги.

## Заголовки, классы и доступность

На странице один h1 — главное предложение первого экрана. Основные темы используют h2,
подтемы и карточки — h3. Каждый section связан со своим заголовком через aria-labelledby
и соответствующий id. У изображений есть alt с описанием, у полей — оборачивающие label.

Классы отражают назначение: hero-request — заявка на первом экране,
project-description — описание проекта. Имена вроде block1 не используются.
Наличие класса само по себе не меняет внешний вид: это имя для выбора элемента в CSS
или JavaScript. Отдельные стили под каждый класс в этой работе не требуются.

Заголовки и абзацы добавлены в тематические разделы, списки, формы и изображения —
туда, где они нужны по смыслу. В каждый технический контейнер не вставляется
одинаковый набор элементов: например, меню содержит ссылки, а не форму заявки.

## Как подключаются файлы

1. Корневой index.html открывает src/index.html через meta refresh; обычная ссылка
   остаётся запасным способом перехода.
2. src/index.html подключает assets/styles/style.css через link.
3. style.css импортирует global.css, fonts.css и utils.css из той же папки.
   Эти файлы сохранены с предыдущей работы.
4. Изображения подключаются через img с относительными путями assets/img/...
   SVG — обычные локальные изображения; библиотеки для них не нужны.
5. Перед закрывающим body подключается index.js. К этому моменту разметка уже прочитана.
6. Ссылка с download скачивает assets/materials/project-checklist.txt.
7. Ссылки вида #team переходят к элементу с id="team". contacts.html открывает
   сохранённую страницу контактов из предыдущей работы.

## Учебные формы

У форм есть разные классы и общий атрибут data-demo-form. JavaScript выбирает
только эти три формы через querySelectorAll и добавляет обработчик submit.
required требует заполнения поля, type="email" проверяет формат адреса средствами браузера.
type="tel" обозначает телефон, но сам по себе не проверяет формат номера.

После успешной встроенной проверки браузер вызывает submit. preventDefault отменяет
отправку и перезагрузку. textContent выводит сообщение в .form-status внутри конкретной
формы. role="status" помогает сообщить результат пользователям экранных дикторов.
Данные никуда не отправляются и не сохраняются. Это демонстрация без серверной части.
Памятку можно скачать отдельно, не оставляя контакты.

## Проверка вручную

Откройте корневой index.html. Проверьте переходы меню и страницу контактов,
наличие разделителей, раскрытие FAQ и загрузку всех иллюстраций.
Попробуйте отправить пустую форму и ввести некорректный email: браузер должен
показать ошибку. При корректном заполнении появляется сообщение без перезагрузки.
Проверьте скачивание памятки. Точное сходство размеров и расположения с Figma
не является критерием этой лабораторной работы.


## Уточнение вложенных блоков по обводке

- hero-content объединяет описание и заявку слева; hero-image находится снаружи
  этой группы, но внутри общего hero.
- service-item — отдельная услуга внутри services-list.
- industry-item — отдельная отрасль внутри industries-list.
- project-navigation-item — пункт навигации по проектам.
- footer-content объединяет внутреннюю контактную и навигационную область подвала.
  Заголовок организации и подпись copyright остаются вне этой группы.
- footer-contact-list — список контактов, footer-contact-item — отдельный контакт.
  address сохраняется внутри группы и обозначает только контактную информацию.

Общие группы оформлены через div, поскольку самостоятельной темы с отдельным
заголовком у них нет. Для повторяющихся пунктов используются существующие li
с классами, без лишних div. Эти изменения уточняют структуру, а не оформление.
